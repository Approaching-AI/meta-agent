# Roadmap 累积

`doc/roadmap/` 用来累积暂时不能立即实现、但已经值得提前思考的功能想法和设计方案。

## 基本用法

当一个 agent 正在处理当前功能时，人类可能提出新的功能想法，或者 agent 自己发现了值得纳入未来规划的方向。默认不要打断当前实现去做新功能，可以先围绕这个想法进行一次 Plan Mode 或类似的规划与演练，再把结果保存到这里。

每个 Roadmap 条目推荐使用一个独立目录，例如：

```text
doc/roadmap/<topic>/
└── plan.md
```

`plan.md` 只是推荐的主入口。条目可以按需要包含调研记录、设计草图、实验结果、问题清单或其他材料，不要求统一模板、固定深度、状态字段、优先级或审批流程。

如果当前使用的 Plan Mode 不允许直接写文件，先完成规划，再在可写的阶段把最终计划保存到 Roadmap 目录。

## 与当前工作的关系

- Roadmap 是未来工作的设计沉淀，不是任务队列，也不是自动调度清单。
- Agent 不需要在每次 session 开始时扫描全部 Roadmap；只有在想法刚出现、当前任务收束、或用户要求继续某个方向时按需查看。
- 是否创建条目、何时阅读、是否开始实现，由 agent 根据当前上下文自行判断。
- 开始实现后可以继续保留并更新原条目，把实际结果记录到项目的 `meta-log/` 或稳定文档中；不要求重命名、移动或删除 Roadmap 条目。

## 目录边界

这里的路径指宿主项目根目录下的 `doc/roadmap/`。引用 `meta-agent` 的项目应把自己的 Roadmap 写在自己的仓库中，而不是写入 `meta-agent` submodule 的文档目录。
